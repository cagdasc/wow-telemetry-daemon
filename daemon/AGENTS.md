# Daemon Agent Guide

Read the workspace-root `AGENTS.md` for the system architecture and current WebSocket contract.

## Responsibilities

- Tail `WoWCombatLog.txt` out of process.
- Recognize and parse combat-log events from bytes, using `memchr` for scanning.
- Write one typed event per log line as JSON lines to stdout and broadcast one frame per event to WebSocket clients: Protobuf binary by default (`--format protobuf`), JSON text with `--format json`.
- Keep the daemon independent from client-specific storage, metadata, and presentation.

## Constraints

- Preserve bounded queues, low memory use, and current event ordering.
- Keep byte scanning and field extraction allocation-light. The current parser allocates its field `Vec` and may
  allocate to unescape quoted fields; JSON serialization also allocates.
- Preserve the raw ordered event fields and support quoted commas, escaped quotes, `nil` fields, and event-specific
  layouts.
- Publish unknown event names and malformed lines as typed fallback events; retain unknown fields or malformed raw
  bytes and a parse reason instead of dropping those records.
- Keep the JSON property names, string ID values, and timestamp semantics in the root contract. `proto/wow_telemetry.proto`
  is generated by `scripts/generate_combat_log_artifacts.py` (with `src/proto_events.rs` and the client mapper); field
  numbers follow spec order, so regenerate and build both services together. Coordinate serialization changes with the client.
- Surface file, parse, serialization, and network failures. Do not silently drop events or replace errors with
  success-shaped defaults.
- Keep the listener bound to localhost by default. If documenting or changing LAN binding, state that WebSocket traffic
  has no authentication or encryption.
- Keep dependencies focused. Use clear Rust ownership and explicit error types; use `thiserror` or `anyhow` only where
  their error model fits.

## Streaming, replay, and clearing

- Every frame gets a monotonic `seq`; `websocket.rs` keeps a 10 MB in-memory replay ring (`ReplayBuffer`). Preserve `HELLO`, `RESUME`, and `REPLAY_GAP` semantics and the epoch-per-restart rule.
- `LOG_CAUGHT_UP` is emitted by `tailer.rs` once per idle period after available lines are read; clients rely on it to close batches.
- `CLEAR_LOG` truncates the file (`set_len(0)`), rewinds the reader, and empties the replay buffer (`clear_replay`, then `LOG_CLEARED`). WoW keeps writing at its old offset, so the file starts with NUL bytes; the tailer strips leading NULs and skips blank lines.
- In tests, read `HELLO` before broadcasting; frames sent before a client registers are not delivered live.
- Do not add per-event sleeps; they only reduce throughput. Raise buffer sizes or coalesce writes instead.
- `cargo test` runs on Linux and finishes in seconds. A hang means a test deadlock. Release builds target `x86_64-pc-windows-gnu`; keep them warning-free.

## Validation

Run `cargo test` from `daemon/`. For protocol changes, also build/test the client and verify the actual serialized event
shape.
